# 周报生成器（Weekly Report）

## Overview

帮助用户把零散的工作记录整理成一份结构清晰、重点突出的周报。核心流程：收集素材 → 分类归纳 → 按模板生成 → 确认输出。

## 工作流程

### 第 1 步：收集素材

按以下优先级收集本周工作内容：

1. **用户直接口述**：用户在对话中描述的工作内容
2. **工作笔记文件**：查找工作目录中的笔记（如 `notes/`、`todo.md`、`*.md` 日志文件）
3. **Git 提交记录**：如果当前目录是 git 仓库，运行 `git log --since="1 week ago" --pretty=format:"%h %s" --no-merges` 获取本周提交

如果三类素材都拿不到，向用户询问：「请简单说说你这周做了哪些事，我来帮你整理成周报。」

### 第 2 步：分类归纳

把素材归入四个类别（没有内容的类别直接省略，不要编造）：

- **本周完成**：已交付、已完成的事项
- **进行中**：有明确进展但未完成的事项（标注进度百分比或状态）
- **问题与风险**：遇到的阻塞、依赖、风险点
- **下周计划**：已明确的下一步安排

### 第 3 步：按模板生成周报

使用 `assets/weekly-report-template.md` 模板生成周报，遵循以下写作规则：

1. **每条工作用「动作 + 结果/数据」描述**，例如：「完成登录模块重构，接口响应时间从 800ms 降至 200ms」
2. **按重要性排序**，最重要的放最前面
3. **合并同类项**，琐碎小事合并成一条
4. **不编造内容**，素材中没有的信息（如数据、进度）留占位符 `[待补充：xxx]`
5. **总量控制在 10 条以内**，每条不超过 50 字

### 第 4 步：确认与输出

1. 生成周报后先展示给用户
2. 明确询问：「需要调整语气（更简洁/更正式）、补充内容，还是导出为文件？」
3. 用户确认后，将周报保存为 `weekly-report-YYYY-MM-DD.md`（日期为当周周五）

## 示例

用户说：「帮我把这周的工作写成周报，我周一修了登录 bug，周三上线了新搜索功能，还在做数据看板。」

生成结果应类似：

```markdown
# 周报（2026-11-02 ~ 2026-11-06）

## 本周完成
1. 修复登录模块 bug，恢复正常登录流程
2. 新搜索功能上线

## 进行中
1. 数据看板开发中 [待补充：当前进度]

## 下周计划
[待补充]
```
